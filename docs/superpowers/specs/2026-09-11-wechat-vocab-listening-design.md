# 微信听音背单词小程序设计说明

## 目标

在现有网页版本之外新增一个可直接导入微信开发者工具的原生微信小程序。用户可以自行录入英语单词，自动查询美式音标和中文释义，保存前人工确认；复习时先听美音，再选择显示答案或进入下一个单词。

本次不预置“常见英语 900 词”，不删除或替换现有网页版本，也不承诺任何免费第三方词典永远在线。程序必须在查询失败时保留手动录入能力，并清楚说明失败原因。

## 方案选择

### 采用方案：原生微信小程序 + 本地词库 + 可替换的在线查询服务

小程序界面、复习流程和词库数据全部使用微信原生能力。查词和音频地址由独立模块统一处理，首版可直接调用公开词典；以后申请正式 AppID 或增加云函数时，只替换服务配置，不重写页面。

优点是导入微信开发者工具后即可预览，维护简单，词库不会因为网络故障而消失。限制是正式发布前必须在微信公众平台配置合法服务器域名；公开词典本身也可能限流或变更。

### 未采用方案：把现有网页嵌入 `web-view`

改造最快，但依赖已备案业务域名、网页兼容性和浏览器语音接口，无法真正解决 iPhone 端发音不稳定以及微信域名限制，因此不采用。

### 未采用方案：首版即建设自有后端词典

准确性和可控性最好，但需要服务器、域名、备案、数据库和持续费用。当前个人自用阶段成本过高。架构会保留日后接入自有服务的接口，但首版不建设后端。

## 项目结构

微信版本放在仓库的 `wechat-miniprogram/` 目录，旧网页文件继续保留在仓库根目录。

- `app.js`、`app.json`、`app.wxss`：小程序入口、页面注册和全局样式。
- `pages/index/`：唯一主页面，包含“复习”和“词库”两个标签页。
- `services/dictionary.js`：查询美式音标、中文释义和可用音频地址；屏蔽不同第三方接口的数据结构差异。
- `services/request.js`：封装 `wx.request`，统一超时、状态码和微信域名错误。
- `utils/storage.js`：词库、设置和查询缓存的本地存储与数据迁移。
- `utils/phonetics.js`：音标清洗、从左到右显示及美音候选排序。
- `utils/review.js`：随机/顺序复习和下一词选择。
- `tests/`：可在电脑上运行的纯逻辑测试，不依赖微信界面。
- `project.config.json`：微信开发者工具项目配置，默认使用测试配置，用户取得正式 AppID 后可替换。

## 页面与交互

### 复习页

页面打开后从已有词库选择一个单词，但不显示拼写。用户点击“播放”听美音；点击“显示答案”后显示英文单词、美式音标和中文释义；点击“下一个”继续。页面提供随机/顺序切换和语速选择。

没有词汇时显示明确空状态，并提供“去添加单词”按钮。播放失败时保留当前单词，显示可理解的原因和“重试”按钮，不自动跳过。

### 词库页

用户输入英文单词后点击“自动查询”。程序只接受由英文字母、连字符或撇号构成的单词/短词，先规范大小写，再查询资料。

查询结果填入“美式音标”和“中文意思”输入框。用户始终可以修改后再保存。结果来源可靠时显示“已找到，请核对后保存”；只得到备用翻译或信息不完整时显示黄色提醒；完全失败时不阻止手动填写。

词库列表支持搜索、单词发音、编辑和删除。删除必须二次确认。重复录入同一单词时更新原记录，不生成重复项。

### 备份

微信小程序首版采用文字备份：点击“复制备份”把 JSON 数据复制到剪贴板；“导入备份”粘贴 JSON 后校验并合并。无效数据不会覆盖现有词库。

## 查词与准确性规则

“确保正确”在产品上落实为来源分级、稳定选取和人工确认，而不是把任何单一免费接口视为绝对正确。

1. 优先读取词典明确标记为 `US`、`American` 或 `en-US` 的 IPA；没有标记时才使用通用 IPA。
2. 不把英国音标标成美音。只有英国候选时，音标栏留空并提示手动确认。
3. 所有音标统一清洗为 `/.../`，保留 IPA 字符，界面强制从左到右显示，避免中文环境造成视觉倒序。
4. 中文释义优先使用词典提供的中文翻译；机器翻译只能作为“待核对”的备用结果，并在保存前明确提醒。
5. 对曾经出错的 `tool`、`refresh` 等词建立小型校准测试，而不是在界面代码里散落特殊判断。
6. 查询缓存带有版本号。查询规则升级时自动忽略旧缓存，避免旧错误长期留在手机中。
7. 保存记录包含查询来源和确认状态；用户手动修改或确认后标记为“用户已确认”。

## 美音播放

使用 `wx.createInnerAudioContext()` 播放查词结果中的美式音频地址。若词典只返回英国音频，则不将其作为美音播放。没有可靠音频地址时，可使用配置中的美式 TTS 地址作为备用；两者均失败时展示错误，不播放错误口音冒充美音。

正式发布前，音频域名和查询域名必须加入微信公众平台的合法域名配置。开发者工具测试阶段可以临时关闭域名校验，但项目说明必须指出这只用于预览，不能代替正式配置。

## 数据模型

每个词条包含以下字段：

```js
{
  id: "稳定的本地唯一标识",
  word: "tool",
  phonetic: "/tul/",
  meaning: "n. 工具；用具",
  audioUrl: "https://...",
  source: "dictionary-provider",
  confidence: "verified | review | manual",
  createdAt: 0,
  updatedAt: 0
}
```

本地存储使用带版本号的对象，而不是直接存裸数组。读取旧格式时迁移，迁移失败时保留原始备份且不清空用户数据。

## 错误处理

- 网络断开：提示检查网络，可重试或手动填写。
- 微信未配置合法域名：明确提示需要在公众平台配置，不笼统显示“查不到”。
- 单词不存在：提示检查拼写，不保存空白查询结果。
- 部分结果：保留已查到字段，将缺失字段标出，允许用户补充。
- 音频失败：停止加载状态并允许重试，不切换单词。
- 本地数据异常：跳过损坏记录，保留可恢复内容，并提示先导出备份。

## 验证标准

### 自动测试

- `tool` 能得到美式音标 `/tul/`，且中文释义包含“工具”。
- `refresh` 能得到美式音标 `/rɪˈfrɛʃ/`。
- 英国候选不会覆盖明确的美国候选，也不会被错误标为美音。
- 嵌套词典响应不会再次出现遍历参数丢失导致的查询崩溃。
- 音标清洗后方向和斜杠格式稳定。
- 重复单词合并、无效备份拒绝、旧数据迁移均通过测试。
- 随机和顺序复习不会在有多个词时立即重复当前词。

### 人工验收

- 微信开发者工具可以导入并编译项目。
- iPhone 预览中可新增、查询、修改、保存、播放、显示答案和切换下一个。
- 关闭并重新打开小程序后词库仍存在。
- 查询失败、音频失败和空词库状态均有明确中文提示。
- 复习答案中的 IPA 从左到右显示，没有倒序或字符错位。

## 交付范围

本轮交付包括微信小程序源码、电脑端逻辑测试、导入说明和一个可下载的 ZIP 压缩包。代码同时提交到现有 GitHub 仓库的 `wechat-miniprogram/` 目录。

本轮不包括微信公众平台注册、实名认证、备案、正式 AppID 申请、第三方域名授权和微信审核发布，因为这些步骤必须由用户本人登录并确认主体信息。完成源码后，将提供逐步操作说明，并尽量把需要手动完成的步骤压缩到最少。
